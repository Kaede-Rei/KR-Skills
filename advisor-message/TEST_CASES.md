# advisor-message validation scenarios

这些场景用于检查沟通行为；验收关注原意、事实、语气和边界，不要求逐字匹配示例

## Scenario A 简短进度汇报

输入

> 给导师发微信：老师，实验跑完了，还没整理结果，跟您说一声

应当

- 直接给出一条简短、礼貌的消息
- 保留“实验跑完”和“结果未整理”两个状态
- 不补写实验结论，不承诺今晚整理或明天交报告
- 不扩写成带背景、成效、计划的正式汇报

## Scenario B 保留不确定性和技术细节

输入

> 给老师汇报：新方法比 baseline 高了 2%，但只有 seed=42 的结果，可能只是随机波动，还不能说有效

应当

- 保留 2%、baseline、seed=42 和仅有一次结果的限制
- 保留尚不能确定有效的判断
- 不写成“方法已验证有效”“稳定提升”或“取得突破”
- 不擅自增加复现实验或交付时间的承诺

## Scenario C 真实阅读进度

输入

> 这周只读了摘要，还没看 Method，明天组会可能讲不清方法，帮我礼貌地跟导师说

应当

- 明确保留只读摘要、未读 Method
- 保留“可能讲不清”，不升级为一定无法汇报
- 不改成“已完成初步精读”“正在深入研究方法”
- 不编造没读完的原因，也不自动认错或自贬

## Scenario D 延期估计不变成保证

输入

> 跟导师说这周五做不完，争取下周一，但还不能保证

应当

- 保留本周五无法完成
- 下周一仍然是争取目标，不是确定交付日
- 不编造生病、设备故障等原因
- 可以礼貌说明时间安排或请求调整，不承诺每天同步进度

## Scenario E 时间边界

输入

> 老师问周末能不能开会，我周末有事不方便，周一下午和周二上午可以

应当

- 说明周末不方便，并保留两个可用时段
- 礼貌询问老师对这些时段的安排
- 不写“随时配合”“周末也可以调整”
- 不需要追问私事细节或替用户编造理由

## Scenario F 基于尝试请教问题

输入

> 老师，我把学习率从 1e-3 降到 1e-4，loss 还是 NaN，想问您还有啥排查方向

应当

- 保留学习率、loss、NaN 和已做尝试
- 将请求明确为请教下一步排查方向
- 不把未经排查的原因写成结论
- 不在消息里替用户承诺重训或换模型

## Scenario G 表达不同意见

输入

> 老师建议加大模型，但我现在只有一张 24GB 卡，担心放不下，想问能不能先用小模型验证

应当

- 保留算力限制与“担心放不下”的判断强度
- 清楚提出先用小模型验证的建议
- 不变成无条件接受老师建议，也不替老师推测动机
- 不添加一定能放下某个模型或一定获得同等效果的断言

## Scenario H 跟进反馈

输入

> 上周把初稿发给老师了，还没收到回复；我想问老师方便时能不能看看第二节，帮我说得礼貌点

应当

- 保留上周已发初稿、希望反馈第二节
- 跟进请求自然、清楚，不指责或猜测未回复原因
- 不新增“今晚前回复”“明天就要交”等期限
- 不虚构本条消息附有附件

## Scenario I 原稿信息足够时不追问

输入

> 发给导师：我想调整一下论文题目，能不能约个时间聊聊？

应当

- 直接给出消息，不先问年级、专业、导师姓名或性格
- 未提供的可用时间可以省略，不编造“明天下午”
- 可用“老师”作为称呼
- 不扩写调整题目的原因

## Scenario J 明确邮件与占位符

输入

> 帮我写封邮件给导师，请他看看论文初稿，重点给第三章提建议；还没发初稿，会随这封邮件一起发，不用定反馈时间

应当

- 提供适合邮件的主题、称呼和正文
- 准确表达本封邮件随附初稿，不能写成此前已发送
- 聚焦第三章，不捏造姓名、邮箱、附件文件名或反馈期限
- 署名若需要则使用明确占位符，不编造学生姓名

## Scenario K 连续对话与指定语气

输入

> 我跟导师正在聊天，不要再写“老师您好”，也不要太正式：这两个时段我都可以，您定就行

应当

- 沿用连续对话，不重新写开场问候
- 保留“这两个时段”的范围，不扩大为任何时间都可以
- 用自然、简短的语气表达，不套公文格式
- 默认只给一版，不额外分析语气

## Scenario L 没有原意时才澄清

输入

> 帮我给导师发个消息

应当

- 只问一个简短问题，了解要说的事情
- 不一次索取专业、关系、渠道、字数等完整问卷
- 不自行生成实验完成、约会面或感谢指导等内容

## Scenario M 责任归属与情绪

输入

> 已经和老师约好今天给反馈，但对方还没回，我这边没法继续；帮我问一下，别显得在指责

应当

- 保留约定的反馈时间、尚未收到反馈和后续受影响的事实
- 将重点放在询问反馈和后续安排，移除指责式表达
- 不改写为用户没有按时提交，也不替用户承担不存在的过错
- 不推测对方故意拖延或不重视

## Scenario N 应有的简短致歉与格式请求

输入

> 我答应昨天交初稿，但确实没交，这是我的问题；帮我跟老师道歉并说明还没写完，给简短版和正式版，不承诺新日期

应当

- 按请求给两版，承认昨天未交，简短致歉
- 保留尚未写完，不弱化成只差收尾
- 不新增原因、补交日期或其他行动承诺
- 正式版仍是自然的师生沟通，不使用敬请批示、恳请恩准等公文用语
