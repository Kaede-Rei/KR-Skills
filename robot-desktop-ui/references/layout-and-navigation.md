# 布局与导航

用于页面重构、子页统一、窄栏整改、滚动与模型工作区排版；以 SerialArm-Core `76326c0` 的布局契约为基线，V2 页面分类见 [布局配方](layout-recipes.md)，沿用目标项目已有的渲染框架

## 固定层级

```text
窗口外壳
├─ 当前机械臂与主导航侧栏
└─ 当前位置、环境与运行状态
   └─ 页面标题与页面操作
      └─ 页面正文
```

窗口操作区、导航、页面标题、任务按钮各自保持明确归属；窗口拖动区不能吞掉按钮点击；主内容单独滚动，侧栏在需要时独立滚动

基线侧栏约 208px、窗口栏 44px、位置栏 42px；内容页最大宽度 1480px，普通分区间隔 24px；这些是起点，布局以容器可用宽度与内容为依据

同一层级的页面共享标题字号、说明位置、操作对齐和正文起点；顶层标题不在某页左对齐、另一页又嵌到大卡片内部

## 三类切换分开表达

| 层级 | 表达 | 适用例子 |
|---|---|---|
| 主页面 | 侧栏；图标、文字与中性选中底 | 准备状态、参数配置、控制工作台、模型查看 |
| 同一工作区的子页面 | 横向文字导航与活动下划线 | 控制至运行监视、几何标定工具、动力学标定工具 |
| 同一字段的互斥值 | segmented control 或 radio 选项 | 主题、语言、ON/OFF、惯性来源 |

子页面导航统一字号、内边距、hover、focus、活动下划线和内容起点；不要一处像选项卡，一处像入口营销卡片，一处只剩没有反馈的裸文字

导航项确实切换页面时使用当前项语义，例如 `aria-current="page"`；若采用真正的 tablist，完整实现 tab、tabpanel 与键盘模型；不能只加 `role="tab"` 而保留不相符行为

长子页名称可以换行或在有界导航区滚动；保留完整名称和活动标识，不能靠压小字号解决；选择状态和当前焦点分别可辨认

活动指示器与正文切换规则见 [动效与滚动](motion-and-scroll.md)；不得通过叠加旧正文来制造平滑

## 准备状态：全宽主流程与全宽工具

```text
下一步建议与直接操作
准备进度
连接、配置等状态概览
────────────────────────
连接前配置 / 运行检查 / 基础标定
────────────────────────
工具与记录
  首次接入 / 专项标定 / 控制配置检查 / 检查记录
```

主流程按纵向全宽展开；“工具与记录”是后续的全宽区域，不再作为被挤窄的右侧栏；其中每项给出名称、简短用途和相应操作

状态概览可在宽容器中四列，较窄时重排为两列；检查行的说明和操作在空间不足时上下排列，不能把长说明挤成一字一行

运行检查、基础标定等流程级折叠使用轻分隔；不必为每个状态行都套大卡片；组件层级见 [组件与反馈](components-and-feedback.md)

## 参数配置：检查全宽，左栏只导航

```text
Profile 名称、保存状态                 重新加载 / 保存
配置来源与完整检查区（全宽）
───────────────────────────────────────────────
分组导航约 180px │ 当前分组标题与说明
                │ 参数字段与折叠卡片
```

保存上下文与检查区放在编辑布局上方；必填项、运行限制、映射等长检查信息不放进 180px 导航栏；左栏只承担分组选择，必要时有短副标题

编辑区使用 `minmax(0,1fr)`，字段网格按标签与数值的最小可读宽度换列；长设备路径、URDF 路径和错误信息可以完整查看，不撑破页面

保存栏可 sticky，但焦点字段、锚点跳转和滚动到错误项时要预留顶部遮挡距离；保存状态明确区分已加载、未保存修改、保存成功

基线在配置容器约 650px 以下切为单列，分组导航变为可换行的横向组；不要保留窄侧栏同时继续挤压编辑字段

参数组以有边界的折叠卡片组织；嵌套组使用更轻的底色和边界；固定展示的字段组可用 `fieldset/legend`；无需为了视觉统一让必填项默认隐藏

## 机器人工作页：共用操作栏与任务结构

控制工作台、几何标定、动力学标定与启动适配层复用顶部连接工具和机械臂操作栏；连接按钮位于标题操作区，采用 brand-solid / brand-ink；串口选择与扫描在同一区域

操作栏在宽容器中的四象限固定为

| | 左侧 | 右侧 |
|---|---|---|
| 上方 | 机械臂状态与状态值 | 使能 / 停放并失能 / 立即失能 |
| 下方 | 当前位置刚性保持 / 柔性恢复 / 清除故障 | 当前操作条件提示 |

```css
.robot-operation-bar {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  grid-template-areas: "state power" "recovery guidance";
  gap: 12px 16px;
}
```

右下提示例如“连接工作台后可使能机械臂”，不插进右上三个按钮之间，也不跟着左下恢复按钮跑；左侧分组起点一致，右侧分组靠右；空提示不预留大片空白

窄窗口按相同语义分组重排，按钮可换行；不要把失能操作藏进三点菜单来换空间；可用条件、连接优先级见 [机器人状态与连接](robot-state-and-connection.md)

操作栏下方通常采用左模型、右任务两栏；模型视图稳定，右侧统一子页导航与正文分区；任务内部以轻分隔组织，避免卡片套卡片

## 模型查看：滚动可达与关节对应

宽布局为树、三维视图、检视器三栏；基线 `208px minmax(320px,1fr) 280px`；工具区在上，关节预览在三栏之后

树与检视器在各自有限高度内滚动；三维视口具有明确高度；关节预览进入页面正常滚动流，不放进会截断末尾行的固定高度祖先

基线模型容器约 900px 以下把检视器移到下一行，约 600px 以下树也单独成行；按真实容器而非假设屏幕分辨率判断

每个关节使用一组独立控件

```text
joint 名称                              当前值 °
滑动条（同一行或下一行）                数值输入框
最小值 °                       最大值 °
```

标签与输入通过 id 关联；关节名允许合理换行；单位贴近数值；滑动条、输入框和上下限来自同一条数据记录；不能让下一关节的标签看起来属于上一条滑动条

普通长度列表使用页面滚动；只有内容确实属于局部工具时才嵌套滚动；对每个 `overflow:hidden/clip`、固定高度与 sticky 祖先检查底部可达性，避免看得到标题却永远滑不到控件

模型保留、预加载、暂停和恢复见 [模型生命周期与性能](model-lifecycle-and-performance.md)；布局变动不应自行触发模型资源重建
