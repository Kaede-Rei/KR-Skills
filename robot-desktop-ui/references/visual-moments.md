# 工程视觉焦点

用于让用户快速理解模型、测量、趋势或系统关系；先确定 [页面任务](art-direction.md)，再选焦点；视觉焦点可以是静态模型或图表，不要求动画

每个页面最多一个主要焦点，复杂工作页可有一个辅助焦点；主次通过面积、位置、层级与必要对比表达，不用持续发光、放大或移动抢注意；故障和安全操作始终保持可辨与可达

## 四种焦点

| 焦点 | 回答用户的问题 | 组成与数据契约 | 边界与回退 |
|---|---|---|---|
| Robot Model Focus | 当前对象在哪里，和其他结构是什么关系 | 模型、当前选择、坐标系、关节与 COM 图例；写明实测/离线预览/参考叠影及其来源 | 保留 XYZ、Joint Axis、COM 工程色；加载或失败显示实际阶段；模型不可用时提供对象树和必要属性 |
| Calibration Moment | 现在处于哪一步，测量和预期差多少，结果是否经过验证 | 当前阶段、前置条件、测量值与单位、预期/参考、残差及验证结果；必要预览与当前测量同步 | 采集、计算、验证和保存分开；失败可回看有效测量；不能用进度动效生成成功状态 |
| Telemetry Moment | 哪个趋势或偏差值得关注，它发生在何时 | 一幅主要趋势、时间范围、来源、新鲜度、图例、关键指标；实测/目标/估计/参考保持一致 | 缺口与断流明示；不默认截轴放大结论；无样本或过期时保留时间与原因，不能显示伪零值 |
| System Topology Moment | 哪条链路或实体与当前异常相关 | 控制器、通信、传感器和执行器的实体与连接；节点 id、连接方向、链路状态和更新时间 | 示意关系与实时状态区分；状态不靠颜色；断连不删除实体；无拓扑数据时显示真实列表或明确示意 |

## 模型焦点的安排

只突出当前任务需要的图层；坐标、COM、参考叠影可选择显示，但图例说明始终能找回；选择高亮采用独立叠加，不重写对象本身的工程语义色

相机、模型和工具栏保持稳定；普通数值刷新不重置相机，不反复自动适配；用户主动选择“定位对象”等动作才使用既有可打断相机过渡；实际数据与预览切换不能误导真实机器人姿态

跨页移动焦点复用现有模型实例，各场景保留自己的视图状态；隐藏时暂停，恢复时先按新容器尺寸更新再绘制，详见 [模型生命周期与性能](model-lifecycle-and-performance.md)

## 标定焦点的安排

当前阶段先显示要采集什么及其前置条件，再展示测量与预期的可比证据；单位、参考系、样本数量或实际适用的质量指标与结果放在一起

阶段列表负责位置感，主预览负责解释测量，结果区负责结论；不在三个区域重复同一块大进度图；未验证结果使用准确状态和下一步，不预先显示成功勾选

操作中出现实际故障时在当前阶段说明对象和原因；取消、恢复或重试沿用原流程，焦点不替代机器人操作栏

## 遥测焦点的安排

先确定比较对象和时间基准，相关曲线使用同一时间窗；不同量纲需要独立轴或分图，并清楚标识，避免视觉相邻却不可比较

参考数据使用 Reference 语义与非颜色编码；Success 只表达实际状态；关键阈值和异常区间要有名称或图例，不用品牌强调色暗示正常/危险

固定数值与图例位置；用户正在查看历史或拖动时间窗时按现有逻辑保留上下文，不因新数据强制跳回实时；可见性、线型和图表背景见 [可视化主题](visualization-theme.md)

## 拓扑焦点的安排

位置表达实体层次和链路关系，同一实体的稳定 id 在重绘中保持位置和选择；标签至少能区分名称、类型与实际状态，不把每次数据刷新都转换成重新布局

线型、箭头和文字说明通信方向或关系；如果双向、广播或物理/逻辑链路需要区分，使用已有项目定义并在图例写清，不从图形距离推断网络延迟或设备物理位置

断连时保留结构并标注失效链路与时间；只有真实拓扑改变才增删节点；工程图制作与元数据见 [视觉资产](visual-assets.md)

## 选择与验收

Workspace 通常选择模型，Calibration 选择当前测量，Telemetry 选择主趋势，Diagnostics 可选择相关拓扑；Configuration 的字段编辑本身可以构成视觉主区，不强行为每页添加模型或图形

缩小窗口时主要证据优先保留，辅助焦点移到下方或使用已有折叠；不要裁切单位、图例或失能操作以维持画面构图

验收关注用户能否回答焦点对应的问题、数据来源是否准确、主题/密度变化是否仍可读，以及背景效果是否抢占数据；截图和行为范围见 [验证](verification.md)
