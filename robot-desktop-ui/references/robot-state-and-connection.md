# 机器人状态、连接与操作反馈

机器人桌面 UI 必须把连接条件、机器人状态和可执行动作表达清楚；界面重构使用真实状态，不改变控制权限

操作栏的四象限布局、顶部工具区位置见 [布局与导航](layout-and-navigation.md)；组件行为见 [组件与反馈](components-and-feedback.md)，文案见 [文案与可访问性](copy-and-accessibility.md)

## 区分三种状态

| 状态层 | 回答的问题 | UI 责任 |
| --- | --- | --- |
| Core/服务 | 计算与通信后端是否可用 | 显示后端准备、启动或错误状态 |
| 工作台会话 | 当前 Profile 是否已建立工作台连接 | 提供连接/断开和本次连接配置 |
| 机器人 | 当前是否离线、可使能、已使能或故障 | 显示真实状态与适用操作条件 |

“Core 就绪”不等于已连接机械臂；“连接工作台”不等于使能；页面可见也不代表命令可以执行

状态读数、使能条件与按钮禁用理由来自项目状态机或后端能力；不要仅凭页面名、是否有模型或按钮颜色推断

图形状态单独表达：模型加载、图形故障或救援模式不能冒充机器人故障；图形恢复也不能隐式恢复使能

## 共用机器人操作栏

四象限结构在布局模块集中定义，所有机器人工作页复用同一组件，不按页面自行排列

- 状态与辅助操作形成左组，主要运行操作与条件提示形成右组
- 使能使用主操作样式，停放并失能与立即失能保持各自操作含义
- 立即失能始终具有危险操作的可辨认性；可用条件由运行状态决定
- 条件提示放在对应操作旁的指定位置，说明当前为什么不能执行或下一步是什么
- 当前状态更新立即反映，不能等视觉动画结束才开放或关闭操作
- 窄窗口时按相同分组重排，保持按钮与提示对应关系

不要为统一动画给安全操作加延迟、移动命中位置，或在界面工作中擅自试运行真实硬件

## 顶部连接工具

凡页面顶部提供“连接工作台”，使用同一套串口扫描、选择和连接工具；启动适配层也遵循此规则

工具提供总线（需要时）、串口选择、扫描刷新和连接；连接使用当前选择，扫描按需更新设备列表；使用 brand-solid / brand-ink 表达主要连接动作；正常状态使用独立 Success Token，不能由品牌颜色推断

- 当前顶部选择是发起连接时的实际来源，Profile 的设备路径提供默认值
- 多总线才显示总线选择；切换总线后按项目规则更新相关选择
- 选择的持久化沿用项目现有 launcher/偏好保存流程；SerialArm 的顶部选择会触发保存，不能描述为“只在内存中有效”，也不能因此擅自覆盖 Profile 中的设备默认路径
- 不将选择端口直接解释为连接成功，也不因扫描成功自动连接
- 连接中、已连接或 Profile 锁定时，按现有会话规则限制冲突操作
- 不把串口选择变动用于使三维几何缓存失效

串口名称来自当前扫描或配置数据，不硬编码操作系统路径、设备数量或关节数量

## 串口选择列表

选择器保持有限高度、内部滚动与清晰的当前项；长列表不能从屏幕顶部铺到最底部

- 支持键盘移动、确认、Escape 与可见焦点
- 容器变窄时可截断展示，但完整路径必须可查看
- 当前配置值即使未被本轮扫描发现，也需按项目语义保留并清楚呈现，不能静默改选第一项
- 扫描得到零个端口是成功完成扫描的一种结果，文案写“未发现串口”
- 不将未被扫描发现直接升级为设备损坏或通信失败
- 选项增强应覆盖既有原生 select 的语义与禁用状态，不另立不兼容的值来源

## 扫描使用按钮锚定状态浮层

扫描通常很快，使用从刷新按钮下方展开的 anchored status popover；不使用遮罩或阻塞弹窗

| 阶段 | 显示 | 交互与时长 |
| --- | --- | --- |
| pending | 转圈 + “正在刷新” | 只禁用重复扫描；其他无冲突操作可用 |
| success | “已刷新” + 端口数量或“未发现串口” | 从完成时开始约 `1600ms` 后关闭 |
| error | “刷新失败” + 可读原因 | 从完成时开始约 `3000ms` 后关闭 |

spinner 的速度与外观服从组件体系；成功或失败结果要能被看见，但不人为延长真实扫描耗时

快请求可以直接进入结果状态；不为了展示 spinner 加 sleep 或最短请求时间

## 浮层状态的生命周期

将操作状态与到期时间存放在独立记录中，DOM 只是展示；页头或工作区局部重建不能丢失结果或重新计时

状态记录至少需要区分阶段、详情、关联页面或锚点、固定的 `expiresAt`，以及当前待完成请求

1. 点击时建立 pending 记录并发起一次请求
2. 同一次请求进行中，重复点击复用或忽略，不并发重复扫描
3. 请求成功更新设备列表；请求失败保留真实失败原因
4. 根据完成时间写入唯一到期时间，再显示结果
5. 重建控件时用剩余时间恢复显示，不重新开始完整时长
6. 离开对应页面或锚点消失时关闭该浮层；清理计时器和定位监听

延迟完成的旧结果不得覆盖较新的操作状态；定位在 resize 和相关滚动时跟随触发按钮，并限制在视口内

对非阻塞状态使用 `role="status"`、合适的 `aria-live` 与触发按钮的 `aria-controls`；不主动聚焦浮层

pending 按钮使用 `aria-busy`；结果使用图标和文字一起区分，不能只靠颜色

同一次扫描错误已经在锚定浮层中说明时，不再重复弹全局错误窗口或 toast；若确有独立后果，在相应操作处说明

## 连接、使能与异步结果

连接与使能按项目已存在的权限与状态转换执行；UI 负责传达状态，不创造捷径绕过后端检查

- 连接操作使用当前选中参数；开始前读取实际选择，不能取旧页头中的残留值
- 正在连接时提供能反映真实阶段的反馈，结束后同步更新状态与操作条件
- 失败时保留可修正的选择和当前 Profile，上下文不被清空
- 断开、停放并失能、立即失能保持独立语义；不因视觉相似合并调用路径
- 实测反馈过期时明确表达，不把旧数值当作实时就绪证明
- 状态刷新与导航共享同一业务来源，避免不同页面显示互相矛盾的机器人状态

加载模型、扫描串口和启动工作台是不同操作；它们使用与责任匹配的反馈，不共享一个笼统的“正在处理”遮罩

## 文案与反馈力度

优先使用用户可采取行动的原因，例如“连接工作台后可使能机械臂”；原始错误、后端代码或堆栈按需放进诊断区

区分“默认值”“当前选择”“已连接”“已使能”“已配置”“已测量”和“验证通过”；不能把前一阶段写成后一阶段

扫描失败不要写成“机械臂故障”；图形初始化失败不要写成“连接失败”；错误应归属到真实失败的层

## 验证与交付

优先在项目既有隔离环境里检查：快扫描、延迟扫描、零结果、失败、重复点击、局部重建、离开页面和自动消失

验证 pending 期间其他按钮可操作、焦点不被抢走、一个错误只提示一次、扫描结束不会误连接机械臂

连接参数选择的验证与真实硬件动作分开；界面开发默认使用项目提供的只读或 mock 路径，具体检查范围见 [验证](verification.md)
