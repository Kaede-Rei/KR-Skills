# 按任务选择工作方式

本模块处理设计、实现、评审、原型与经验沉淀；具体视觉和行为由相应模块定义，不在每种工作方式中重复一份规范

## 先确定本次交付

| 用户意图 | 交付 |
| --- | --- |
| 分析、评审、先给方案审核 | 只读检查，给出有依据的问题或完整方案 |
| 修改、修复、实现、重构 | 完成相关界面及必要调用路径，验证后交付 |
| 比较几种设计 | 在隔离原型中提供有意义的不同方案，供选择 |
| 卡顿、重载或资源问题 | 定位实际热点或生命周期错误，修复后做同条件比较 |
| 整理本次已确认的设计经验 | 收集最终修正、解释理由，写入用户指定的文档或 skill |

按上下文理解“优化”等自然表达；不要机械套用上游某个 skill 的只读模式，把已经授权的实现缩成建议；用户明确要求先审核时则止于可审核方案

## 了解现有实现

从影响面读取目标项目：当前 tokens、组件、布局约束、状态来源、更新路径和已有检查入口；追踪触发动作、异步结果、渲染及失效路径

在 SerialArm-Core 内，以当前实现和本包记录的设计契约对照；在其他项目，读取实际组件和数据契约，再落实相同设计语言；不要照搬源项目的文件布局、六个关节名称、设备路径或控制参数

有明确本次要求时直接执行；只有缺失信息会改变关键设计或不可逆选择、且不能从现有项目推断时才询问

## 设计和整体重构

先说明页面主要任务，再安排对象上下文、连接与机器人状态、主次操作、预览和任务内容；先按 [Art Direction](art-direction.md) 确定页面类型、主要焦点和确定性选择，再应用 [布局配方](layout-recipes.md)、[布局契约](layout-and-navigation.md) 与 [设计系统](design-system.md)

保持主页面和子页面的层级；用一套共用组件处理重复结构；把状态、加载、成功、失败、空数据、禁用和较窄窗口一起纳入相关界面

不要为了“苹果风”改变用户已经确认的主色、字体或平台窗口语义；用户要求其他品牌或项目有更具体约束时，在本次明确范围内适配

## 增加、修正和减少动效

先识别目的：即时反馈、空间关系、状态转换或避免突变；继承 [动效与滚动](motion-and-scroll.md) 的 spring 和打断规则

- 补缺失反馈时，从触发控件与受影响内容之间的关系入手
- 处理生硬切换时，检查状态是否被重建、是否从目标值重启、旧内容是否仍在显示
- 处理“太慢”时，先移除等待动画、无用 stagger、普通刷新重播和重复渲染
- 减少装饰动作时保留用户明确认可的短 spring、操作反馈和状态可读性
- 遥测、错误、使能状态和命令确认按真实时间更新；不使用补间制造尚未发生的业务状态

一次动作的有关部分使用一致的节奏；稳定的页面外壳、安全操作和三维画布不随正文移动

## 原型与边界检查

确实需要比较时才建立原型；复用同一套 tokens、真实尺寸和邻近组件，比较布局或交互上的实质差异；不用换色充当不同方案

优先使用现有离线 fixture、原型页面或临时隔离目录；示例数据必须明确是示例，不进入生产 Profile、任务记录或机器人会话；选定方案后再接入正式页面

对本次组件检查可能破坏其含义的数据：长关节名、相似路径、中英文标签、空列表、单条数据、缺失模型、较大表格及适用范围内的窗口尺寸；重要数值、单位和安全状态不能通过截断掩盖

一次局部按钮修改不需要多方案原型，也不需要建立全应用压力测试面板

## 技术与依赖取舍

SerialArm 的参考实现是原生 DOM/CSS/JS 与 Electron、Three.js；同样的设计可以落实到 Qt 等桌面框架

先使用已有组件和平台能力：原生 details/popover、现有 spring 调度、现有选择器和状态播报；检查它们是否覆盖正确的开关、焦点、滚动与失效语义

只有现有能力留下具体缺口时才考虑新依赖，并遵守当前任务的依赖授权规则；不因为上游推荐 Sonner、Motion、Base UI、React 或某状态库就直接安装

在 Qt 中使用相应控件、事件和资源所有权落实同一行为；不要伪造 DOM API；移动端、Expo、Swift 专属开发不属于本版能力，见 [来源覆盖](sources.md)

## 评审

先给出具体问题及其可达触发条件，再说明用户可见后果、源码或实际运行依据，以及建议修改的位置；将已观察的问题与尚待验证的推断分开

按影响排序；无需为没有发现的问题编造一套风险，也无需强制每次评审都输出固定数量的发现或相同大表格；未经授权不写入源文件

## 沉淀设计偏好

只记录用户明确确认或通过实际使用最终保留的规则；同一问题以最后确认结果为准，保留理由与来源

当前有效例子包括：森林绿双主题、真实 Maple Italic、紧凑 hover、四象限状态栏、统一子页导航、单新正文进入、非阻塞串口浮层、折叠滚动连续性与模型生命周期

V2 提案明确替换了旧版本否决绿色主色的决定；默认采用森林绿，不再沿用旧橙色主品牌规则；黑色主按钮、窄信息栏、串口扫描阻塞弹窗和旧正文叠加仍不作为默认值；没有确认的尝试不自动升级为长期规范

只把相关经验写入用户指定的位置；不自动修改私人记忆、全局 agent 设置或其他项目的设计文件
