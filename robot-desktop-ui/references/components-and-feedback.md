# 组件与操作反馈

用于折叠、菜单、选择器、设置控件和任务状态反馈；目标是让同类行为一致、可辨认、可打断，沿用目标项目的原生或现有组件能力，不强制 React 或新的 UI 库

## 先区分控件的职责

| 需要表达什么 | 控件 | 关键行为 |
|---|---|---|
| 按对象提供更多操作 | overflow menu，三点菜单 | 锚定对象、重复触发关闭、外部关闭 |
| 为控件补充短说明 | tooltip | hover 与键盘 focus 可见，不承载必要步骤 |
| 显示操作附近的短状态 | anchored status popover | 不抢焦点；进行中→结果→自动消失 |
| 页面无关的短暂通知 | toast | 不遮挡关键操作；不重复播报同一事件 |
| 要求用户作决定或等待必要前置过程 | dialog / modal loading | 有明确原因、焦点管理与结束条件 |
| 展开同一上下文的内容 | disclosure | 保留当前输入和页面位置 |
| 选择有限互斥值 | segmented control / radio | 明确选中状态，切换立即生效或明确保存 |
| 从较长列表选择值 | select / combobox | 有界滚动、完整值可查、键盘可用 |

不要因为都浮在内容上方就将它们统一写成 toast；浮层类型应由操作关系、是否需要输入、是否需要阻塞决定

## 每个交互对象都有反馈

给按钮、导航项、可点击卡片、折叠标题、菜单项和复选框提供一致的 hover、pressed、focus 和 disabled；只有可点击区域才出现可点击反馈

- 普通 hover 用轻背景、文字或边界变化；主操作使用主题的 brand-hover
- pressed 立即响应，释放后回到与当前 hover/focus 相符的状态
- focus 使用清楚轮廓，不能只靠 hover 表达键盘位置
- disabled 来自实际条件；解释放在附近或通过可访问描述关联，不只放在无法触发的 tooltip 上
- selected 表示持续选择，不能与瞬时 hover 混同

复选框与标签的命中区贴合二者；例如“编程连字”是紧凑的 label，右侧连字示例独立布局；不要让整行空白因 hover 变成一块巨大高亮条

图标按钮有可访问名称；图标不代替主要动作名称；低频图标可补 tooltip，必要操作条件要在界面中可见

## 折叠保持统一语义，容器按层级选

Web 优先使用 `details > summary` 或已有等价 disclosure 组件；Qt 等框架保留相同可访问角色、展开状态与键盘行为

所有折叠使用同一种尖括号：收起朝右，展开朝下；基线标记为 8px、1.5px 描边；标题有一致字号、间距、hover 与 focus；不要混用三角形字符、原生 marker 和另一套图标

使用自定义标记时隐藏原生 marker；标记的旋转进度与内容高度使用同一状态源；`summary` 的可点击边界与视觉标题一致

| 内容层级 | 容器形式 |
|---|---|
| 参数配置中的独立参数组 | 有边界、卡片底、约 10px 圆角；展开标题与正文有轻分隔 |
| 参数卡片内嵌套组 | 较轻边界、次级表面、约 8px 圆角 |
| 准备流程与工作台内部区段 | 轻分隔行，保留统一 disclosure 标记 |
| 原始诊断、来源、简短补充 | 轻量折叠，不再嵌套大卡片 |

统一的是标记、状态、交互与层级规则，不是给所有折叠套同一个大壳；固定可见字段组可用 `fieldset/legend`，不要伪装成可点击的 summary

展开或收起保留已挂载编辑器、输入内容、校验与选择状态；结束隐藏后不让不可见控件接收焦点；收起不能把页面突然顶到顶部；具体高度和滚动连续性见 [动效与滚动](motion-and-scroll.md)

## 三点菜单：避免同次点击关掉又打开

Web 有原生 Popover API 时，优先让 invoker 负责 toggle；不要同时使用 pointerdown 外部关闭和 click 中无条件 show 的两套开关

```js
trigger.popoverTargetElement = menu;
trigger.popoverTargetAction = 'toggle';
```

同一菜单由多个对象共用时，点击另一触发按钮应更新当前对象与锚点；在菜单已打开且对象不同的情况下先切换归属；菜单操作必须读取当前对象，不能保留上一次行的 id

需要具备的行为

- 同一触发按钮再次点击关闭，不在同一事件中重新打开
- 点击外部或按 Escape 关闭；菜单内正常选择不被外部处理器提前截断
- `aria-expanded` 反映实际 open 状态；`aria-controls` 指向真实菜单
- 位置从触发按钮展开；底部空间不足时翻转，左右边缘留余量
- 页面滚动、窗口缩放或触发元素移除时更新锚点或关闭
- 关闭后按合适方式恢复焦点，不能跳回页面顶部

原生 popover 负责顶层与关闭机制，不自动补齐应用菜单键盘模型；若标为 `role="menu"`，检查方向键、Escape、进入与离开；简单按钮列表也可保留原生按钮语义

## 状态浮层按真实操作状态推进

快速串口扫描使用刷新按钮下方的 status popover；spinner 表示请求仍在进行，完成后替换为明确结果，再自动关闭；不阻塞页面、不抢焦点、不人为延长请求

成功与失败的停留时间可以不同；计时属于本次操作状态，不属于某个即将被重建的 DOM 节点；头部局部重绘不能重新开始倒计时，也不能丢失结果

只限制相同操作的重复触发；其他无关按钮继续可用；同一失败不要同时触发浮层、toast 与全屏错误框；具体时长与连接选择规则见 [机器人状态与连接](robot-state-and-connection.md)

首次打开 Profile 且模型必须先准备时，可使用有明确标题的 loading；结束后展示所选 Profile 或可操作的失败状态；模型机制见 [模型生命周期与性能](model-lifecycle-and-performance.md)

## 下拉列表有边界

串口等长列表设置视口内的最大高度，内部滚动；宽度贴合触发控件与内容，在窗口边缘约束；选中项保持可见，不让上百项原生菜单盖住整页

保留触发器、选项、当前值、展开状态和键盘选择之间的语义关系；如果增强原生 select，原始值、change 事件、disabled、校验与 label 必须继续有效

只有需要搜索和自由输入时才使用 combobox；不要为一个三项互斥设置引入完整搜索选择器；扫描结果变化后保留仍然有效的当前选择

## 设置与选择卡片

主题、语言等使用紧凑 segmented control；活动指示器在共同轨道内移动，文字层保持稳定；不要通过复制两个活动标签做过渡

三维后端这种具有标题和说明的选择可以使用卡片；选中卡片采用 brand-solid / brand-ink，说明与勾选符号同时切换；未选中项保留清楚 hover 与 focus；禁用原因不依赖颜色

选择卡片不是子页面导航；切换字段的结果需要重启、保存或其他前置条件时，放在选择区附近说明，不通过动画假装已经应用

## 浮层与对话框的材料

普通卡片使用细边界与很轻的阴影；浮层用更明显但克制的阴影；当前基线 popover 圆角约 10px、dialog 约 18px；不要为“苹果风”把所有区域都变成透明玻璃

浮层内容超长时内部滚动，按钮和必要提示可达；dialog 使用原生焦点约束或等价机制，关闭时返回触发上下文；减少透明度偏好改用不透明表面

颜色、字号、按钮样式见 [视觉与字体体系](design-system.md)；状态播报与文字见 [文案与可访问性](copy-and-accessibility.md)
