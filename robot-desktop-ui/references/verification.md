# 验证相关的可见行为

按本次改变的组件、调用路径和状态生命周期选择检查；复用仍适用于最终版本的已有证据；检查通过且没有已知范围内问题后结束

## 证据必须覆盖所作判断

- 源码检查能确认结构和实现路径，不能证明实际 hover、焦点、打断或滚动已经正常
- 截图适合检查布局、裁切、字体、主题和数值对应关系；菜单开关和动效需要实际交互
- 逐帧记录适合发现旧文字叠加、瞬跳和重启动画；性能比较使用相同模型、输入与图形环境
- 不能运行的部分明确写出尚未验证；不使用无关成功检查替代它

## 按影响面检查

| 改动 | 有意义的检查 |
| --- | --- |
| 主按钮或小型选项 | 正常、hover、pressed、focus、disabled；命中范围与反馈一致，文字可读 |
| 主页面和子页切换 | 快速往返；中间帧只有当前业务正文；新按钮立即可用；稳定区域不移动；普通刷新不重播 |
| 折叠 | 长页中段保持位置；底部必要 clamp 连续；嵌套滚动不带动外层；快速反转、编辑值与焦点保留 |
| 菜单或 select | 同一触发器再次点击、点击外部、Escape、换触发对象、键盘选项；较窄窗口不越界，长列表能滚动 |
| 串口扫描 | 即时与较慢成功、失败、重复点击、扫描期间操作其他控件；页头重建不续期，结果可读并自动消失 |
| 模型生命周期 | 打开 Profile 预加载；跨页复用实例与资源；隐藏后没有 RAF/timer/draw；显示恢复；各预览槽状态独立 |
| 模型失效和性能 | 显式重载、来源/身份/后端变化、上下文失效；失败后仍显示正确 Profile；相同姿态无额外绘制，变化值仍更新 |
| 表单或布局 | 实际支持的较窄窗口与相关语言；必填与错误可见；重要路径可查完整值，数值单位不混行；滚动能到最后控件 |
| 状态或文案 | 使用实际会话状态与部分完成数据；说明区分配置、应用、测量和验证；技术诊断可展开 |

减少动态的切换应立即结束正在运行的动效并留下正确最终状态；影响透明材质或颜色时检查相应偏好与实际对比度

不必为每次改动执行整张表；不把所有主题、语言、窗口和状态机械相乘形成验证矩阵

## V2 视觉截图矩阵

全局主题升级需在目标应用覆盖以下维度；按代表页面和状态组合覆盖各维度，异常状态在对应页面验证，不要求全部笛卡尔积；局部修改只执行相关组合；不适用的页面或状态注明原因，不为凑矩阵新增业务功能

| 维度 | 覆盖 |
|---|---|
| 主题与密度 | Light / Dark；Default / Compact；Comfortable 在目标应用提供时检查 |
| 页面类型 | Dashboard、Workspace、Telemetry、Configuration、Diagnostics、Calibration；Model Inspector 若存在 |
| 系统状态 | 正常、警告、故障、断连；来自受限 fixture 或真实可复现状态 |
| 数据 | 空数据、正常数据、长路径/极端数值/大列表、缺测与断流 |
| 模型 | 加载中、已加载、加载失败；不同展示槽的图层与相机 |
| 窗口 | 常规、窄窗口、高 DPI；记录 viewport、缩放和设备像素比 |
| 控件状态 | hover、pressed、focus、selected、disabled，以及菜单/浮层边缘翻转 |

截图保留修改前后版本，记录应用提交、页面、fixture/数据、主题、密度、窗口与图形环境；相同输入比较；保存在目标项目已有截图位置，随包静态预览只是样例，不替代这些业务页面截图

视觉检查包含：Token 一致性；Page/Surface/Elevated/Canvas 层级；组件和 SVG 尺寸、线宽、对齐；字体真实资源、数值对齐、溢出；图表标题、单位、图例和线型；Reference / Success 区别；实际合成背景上的文字、focus 与必要非文本对比度

## V2 视觉、交互与性能 Finish Gate

全局应用升级完成前，确认旧橙色默认品牌规则已迁移，双主题与 Reference 语义一致，相关 SVG/图表/三维已适配，截图已检查；同时运行上表相关交互、机器人状态、模型生命周期检查，保持 [TEST_CASES.md](../TEST_CASES.md) 的原有行为契约

性能比较使用相同数据、模型、视口与后端，记录现有项目关心的加载耗时、资源创建/读取、重复姿态处理、draw / RAF、布局与 GPU 成本；阈值沿用项目预算或本次明确标准，不发明通用 FPS；检查隐藏暂停、缩放、高 DPI、主题切换、reduced-motion；装饰背景不应引入持续绘制，出现退化时定位具体效果或重建路径

应用 Finish Gate 要求文档与测试同步、无已知范围内视觉/行为/生命周期回归，且有相应运行证据；无法执行的维度写清范围与原因，不能写成全应用验收通过

## 使用现有项目检查

SerialArm-Core 的相关入口位于仓库的 `apps/launcher/scripts/`

| 入口 | 用途 |
| --- | --- |
| `verify.cjs` | Launcher 静态与项目约定检查，需其原有本机运行环境 |
| `studio-ui-fixture.cjs` | 用生产 renderer 和受限离线数据构建 UI fixture |
| `render-studio-ui.cjs` | 检查相关页面、尺寸、语言和主题的实际渲染 |
| `verify-model-lifecycle.cjs` | 实际模型预加载、保留、暂停、失效与姿态更新路径 |
| `verify-model-ghost.cjs` | 参考叠影、实际姿态隔离、资源替换和释放 |

先读取脚本用法及 fixture 允许的操作，再执行适合本次改动的入口；这些脚本依赖应用和环境，不复制进本 skill 作为可移植测试工具

在其他项目中使用该项目等价的检查；不要为了模拟 SerialArm 的目录结构新造测试框架

## 模型结果的范围

记录实测模型格式和图形后端；使用真实 STL 的测试不能替代 GLB 验证，SwiftShader 的结果也不能写成用户 GPU 的帧率保证

## Skill 本身的维护验证

结构检查包括 frontmatter、元数据、相对引用是否存在、来源与许可是否准确，以及入口是否能引导读取正确模块

使用 [TEST_CASES.md](../TEST_CASES.md) 中与本次 skill 改动有关的真实任务做前向检查；评估时只给请求、skill 与必要原始材料，不先透露期待的结论；检查实际输出是否保持范围与产品规则

只有新增或修改了可执行脚本才运行该脚本的必要验证；纯指引更新不需要重测整个机器人应用或连接设备

本包携带 CSS / SVG / HTML 时，另检查原始 Token 与固定上游一致、派生色和透明状态组合、SVG XML 与离线预览渲染；这些证据可证明技能资产可用，应用性能与机器人交互仍需目标应用自己的运行证据
