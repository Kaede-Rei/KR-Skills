# 页面视觉方向与确定性选择

用于新页面、整体视觉升级或缺少主次关系的工作区；只改局部按钮时直接读取对应组件规范，不要求重新做页面规划

Botanical Engineering 的目标是安静、准确、适合长时间工作的工程工作站；品牌与表面取 [主题规范](theme-guidelines.md)，数据和模型取 [可视化主题](visualization-theme.md)，操作方式沿用现有交互契约

## 先识别任务，再选择构成

按以下顺序确定方向；记录在现有设计说明、变更说明或原型旁即可，不为每次修改新增一套配置文件

1. 写清用户当前要完成的动作、关注对象与输入数据，例如“核对当前机械臂跟踪误差”，不只写“做一个好看的监控页”
2. 确定主任务类型；以用户的主要操作和数据关系分类，不根据页面名称或某个组件的外观分类
3. 标出不能移走的连接、状态、操作条件和停止入口；主视觉不能占用这些区域
4. 从 [布局配方](layout-recipes.md) 选择对应配方，再按容器尺寸和内容约束重排
5. 选择一个主要 [工程视觉焦点](visual-moments.md)、已有 [组件](component-library.md) 和确有用途的 [视觉资产](visual-assets.md)
6. 核对双主题、密度、空数据、断流、故障与窄窗口；视觉改变不得改变状态来源、命令前置条件或资源生命周期

## 页面分类

| 类型 | 由什么任务判定 | 首要对象与视觉焦点 | 默认配方与密度 |
|---|---|---|---|
| Dashboard | 判断设备准备情况、任务进展并进入下一步 | 当前状态与下一步；只有确需关系解释时才增加拓扑 | D，总览与主数据；Default |
| Robot Workspace | 在机器人上下文中操作、观察姿态和执行结果 | 模型与当前任务；机器人操作栏始终清楚可达 | W，模型与任务；Default |
| Telemetry | 比较随时间变化的测量、目标和误差 | 一幅主趋势图及其时间范围 | T，主图、指标与数据表；Compact |
| Configuration | 按分组修改、检查和保存参数 | 当前参数组与修改状态，预览是辅助 | C，全宽检查区、分组导航与编辑器；Default |
| Diagnostics | 从日志、告警或异常定位原因 | 事件时间线、选中事件与上下文 | G，日志与详情；Compact |
| Calibration | 按阶段完成测量、计算和验证 | 当前阶段、测量值与结果证据 | K，阶段、预览与结果；Default；引导步骤可 Comfortable |
| Model Inspector | 沿对象结构检查几何、坐标系和属性 | 当前对象与模型中的对应位置 | I，对象树、视口与检视器；Default |

多种任务共存时，先按当前主操作判定：编辑参数用 Configuration，顺序测量用 Calibration，追查事件用 Diagnostics；以图表为主要读写对象才归 Telemetry，以对象选择与属性检查为主才归 Model Inspector；其余机器人操作用 Workspace，总览入口用 Dashboard

同一工作区包含多种任务时保留统一外壳与子页导航；分别为子页面选择配方，不把所有候选布局拼成一个大页面

## 四类选择器的边界

| 选择器 | 已知输入 | 允许选择 | 不能决定的事 |
|---|---|---|---|
| Theme Dealer | 用户主题偏好、已批准主题和实际背景 | 已定义的 Light / Dark、表面、状态与 focus token | 不随机生成品牌色；不改 XYZ、COM 或设备状态含义 |
| Layout Recipe Selector | 页面类型、主要任务、容器尺寸、面板最小可读宽度 | 已定义配方及其重排状态 | 不随机换栏；不为装饰隐藏安全操作 |
| Component Selector | 现有组件接口、所需状态和输入复杂度 | 项目已有组件，其次平台控件，再补具体缺口 | 不因视觉升级安装新组件库或重写成熟行为 |
| Visual Asset Selector | 要解释的数据关系、真实来源、主题与性能约束 | 图表、SVG、工程示意或三维视图 | 不把装饰或示例图当真实设备证据 |

出现多个可用选择时，依次优先：保持现有工程和交互契约、覆盖主任务、复用现有组件、减少必要视线往返、减少资源和维护成本；同一输入应得到同一选择

## 内容构图

- 页面标题表达对象与任务，例如“关节跟踪误差”，说明只补范围或采样上下文
- 一个面板承担一个明确任务；同一状态不在标题、卡片、横幅和 toast 重复出现
- 指标同时展示数值、单位、时间或新鲜度；变量宽度提前保留，避免刷新引起整行移动
- 图例明确写实测、目标、估计与参考；序列与实体一一对应，不用泛称“数据 1”
- 空状态说明当前情况与可执行下一步；加载说明正在准备什么，失败说明实际对象与恢复入口
- 危险、错误和前置条件靠近受影响动作；不把必要条件藏进 tooltip

字体与尺度使用 [设计系统](design-system.md)，术语、状态含义和键盘语义使用 [文案与可访问性](copy-and-accessibility.md)

## 设计历史与完成条件

需要比较方案时记录“任务／选用配方／主要焦点／复用组件／放弃方案的具体原因”；已有设计记录仍适用就继续使用，不为追求变化重新选色或换布局

选用方案应能说明：先看到什么、接下来能做什么、关键工程数据来自哪里、窗口变窄后如何保持可达；实现后按 [验证](verification.md) 检查实际渲染与行为，不把设计说明当作运行结果
