# 三维模型生命周期与渲染性能

模型是跨页保留的工作资源；Profile 打开时准备模型，页面仅决定在哪里展示、使用哪份视图状态和何时绘制

页面结构见 [布局与导航](layout-and-navigation.md)，状态归属见 [机器人状态与连接](robot-state-and-connection.md)，动画与直接操作见 [动效与滚动](motion-and-scroll.md)

## Profile 打开时预加载

打开 Profile 时统一经过预加载流程；正常打开、Library 入口、创建后打开及已有 Profile 切换入口保持一致

准备范围包括

- 解析后的模型描述与 native 模型数据
- 实际使用的 mesh、材质、纹理和必要的几何数据
- 参考叠影需要的资源与 shader 编译准备
- 模型实例可用所需的视图初始化

首次预加载可以使用明确的 loading 界面，完成后再进入工作区；不要只请求模型描述就宣布三维已经准备好

同一有效数据和图形模式的并行调用共享同一个 preparation Promise，避免重复 native 请求或 mesh 读取

模型不可用但 Profile 仍能编辑时，允许进入相应编辑或准备页面；模型故障不应把用户困在旧 Profile

## 生命周期契约

| 阶段 | 责任 |
| --- | --- |
| preparing | 读取数据、准备资源，记录 generation 与身份 |
| visible | 将既有实例挂到当前可见容器，恢复该场景状态并绘制 |
| paused/retained | 保留实例与资源，停止绘制和视图计时器 |
| invalidated | 中止复用资格，正确释放旧资源并重新准备 |
| failed/lost | 显示实际错误，等待明确重试或重建，不把失效实例当缓存命中 |

同一有效 Profile 保留一个可复用的模型视图、renderer 与 canvas；页面切换不等于销毁模型

可以将 canvas 与工具节点转移到隐藏保留容器；显示时重新附着到目标容器，更新 observer，并在新页面首次绘制前完成挂载

不要在可复用挂载路径增加一次不必要的宏任务等待，否则缓存仍会表现为切页空白

## 隐藏时真正暂停

`pause()` 应停止已排队的 RAF、绘制计时器、相机过渡与平滑缩放，禁用不可见的相机控制

隐藏容器或 `display:none` 本身不保证暂停；必须检查没有后台 RAF、timer 和 draw 持续运行

`attach(container)` 负责转移现有 canvas 和工具、解绑旧容器 observer 并观察新容器；挂载期间先保持暂停

`resume()` 按新容器尺寸更新相机与画布，再请求必要绘制；不重复加载模型或重建所有资源

销毁负责释放 model 资源、renderer、监听与 observer；暂停与销毁使用不同入口，不让普通导航误调用 dispose

## 模型缓存何时失效

| 变化 | 处理 |
| --- | --- |
| 普通页面或子页面切换 | 保留实例，切换挂载位置与视图状态 |
| 串口选择或扫描 | 不使几何与图形资源失效 |
| 明确重新加载模型 | 失效并重建 |
| Profile、模型身份、来源或资源路径变化 | 核对来源 key 后失效 |
| 图形后端或模式变化 | 按实际后端约束重建，必要时明确提示重启 |
| 图形上下文丢失、renderer 失败 | 取消命中资格，走故障与恢复路径 |

缓存 key 只包含实际决定模型或图形资源的输入；不能直接使用含串口等无关设置的整个配置指纹

项目实际提供的 model identity、资源信息和来源 key 优先于自行猜测；不要为复用引入与模型责任无关的缓存机制

## 防止过期加载覆盖当前 Profile

数据请求、实例准备与参考叠影都需要对应的 generation 或等价取消标识；结果提交前核对当前请求、模型来源与身份

快速从 Profile A 切到 B，A 后完成时只释放或丢弃 A 的结果，不能挂载到 B 的页面

旧准备任务的 `finally` 只能清理属于自己的 pending 状态；不能把较新的准备标记清空

失败时收起对应 loading，保留当前选中的 Profile 可编辑；显示实际原因并提供项目已有的重试或重载入口

不要把失败吞成一个看似成功的空模型，也不要退回显示上一 Profile 的残留画面

## 各展示场景保存独立视图状态

共享模型资源不等于共享所有 UI 状态；模型页、工作台及描述预览按展示场景保存自己的状态

- 相机位置、方向、投影参数与观察目标
- 图层、惯性来源和对象可见性
- 当前选择与自动适配状态

恢复对象可见性时先清空原 Map，再写入该场景快照；只增量合并会把模型页隐藏的 Link 泄漏到工作台

没有快照时使用对应默认视图；恢复时取消旧相机运动，避免其继续拉回上一场景的视角

对用户交互有意义的视图状态可以保留；不能将旧模型对象引用塞入跨模型快照

## 区分实测、编辑预览与参考叠影

| 表达 | 数据来源 | 约束 |
| --- | --- | --- |
| 实测姿态 | 当前有效反馈或 native 状态 | 清楚表达新鲜度与连接条件 |
| 离线/编辑预览 | 用户编辑的目标或预览位置 | 明确是预览，不暗示机械臂已执行 |
| 参考叠影 | 独立参考变换与共享几何资源 | 不修改实测模型姿态 |

切回工作台恢复最新实际姿态；切回模型页恢复其预览上下文，不能把上一个页面的关节值当作另一类数据

叠影优先共享不可变 buffer 和合适的材质；清除某个目标不应销毁仍由主模型持有的资源

模型动作、预览和真实命令入口保持分离；三维渲染完成不改变机器人运动许可

## 先修实际热区

性能检查先区分资源重复加载、重复姿态计算、资源反复创建、无效 draw 与场景本身的 GPU 成本

沿用 SerialArm 的已验证处理

- 保存 frame 名称、位置、四元数的数值快照；比较数值而非对象引用，未变则跳过整套 pose 更新
- 对 COM 单独比较；frame 未变但 COM 变化时仍更新 COM
- 首次创建质心连线、标记和标签；随后修改 buffer 端点和对象位置
- 文字不变时复用 canvas texture，避免每次反馈重画标签纹理
- 只有新增或图层状态变化才做必要的可见性更新
- 状态改变时请求绘制，同一帧合并重复请求；静止且没有其他活动时停止绘制

数值快照要拷贝数组，避免输入对象被原地修改后使比较失效；不要只检查整个 `native` 对象是否相同

COM 从有到无时正确移除并释放专属资源；与主模型共享的资源按明确所有权释放，防止重复 dispose

未经测量，不先降低像素比、mesh 精度或材质质量；确需画质选项时按图形模式表达其代价

## 证据与交付

用实际支持的模型与项目既有离线工具检查：首次预加载、跨页复用、隐藏暂停、场景状态分离、失效重建、加载失败与快速切 Profile

对热点记录前后资源创建/读取次数、重复姿态处理与绘制次数；耗时数据注明输入和运行环境，不承诺通用 FPS

某种资源格式或图形环境失败时准确报告其验证范围；真实 STL 通过不能写成 GLB 已验证，隔离图形运行失败也不能直接归因于新生命周期代码

遵守项目已有检查方法，不将 SerialArm 专属 fixture、脚本或机器人数据整包复制到新项目；不硬编码六个关节、joint6 或设备路径

具体检查选取见 [验证](verification.md)，来源与设计基线见 [来源](sources.md)

## V2 主题变化的资源边界

Light / Dark 切换只更新画布、网格、标签和材质的主题属性，请求必要重绘；不因主题或密度改变模型身份、generation、相机快照或预加载资格，不重建几何、renderer 与共享纹理

XYZ、Joint Axis、Link COM、Total COM 保留工程映射；选中、hover、异常使用独立叠加，见 [可视化主题](visualization-theme.md)；主题适配仍遵守上述暂停、恢复和资源所有权契约
