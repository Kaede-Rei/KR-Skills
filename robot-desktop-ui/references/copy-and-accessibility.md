# 文案与可访问性

用于按钮、状态、设置说明、错误反馈、字段与键盘操作；文案帮助使用者判断当前情况与下一步，保留业务事实和必要技术信息

## 动作直接，状态具体

按钮使用实际动作与对象，避免“执行操作”“确认处理”等无法预测结果的词；同一动作在不同页面保持同名

| 意图 | 基线文案或写法 |
|---|---|
| 建立工作会话 | 连接工作台 |
| 重新枚举设备 | 扫描串口 |
| 应用参数到当前会话 | 临时应用，或明确写“应用到当前会话” |
| 持久化参数 | 保存配置 |
| 保持当前位置 | 当前位置刚性保持 |
| 受控停放后断使能 | 停放并失能 |
| 立即断使能 | 立即失能 |
| 查看底层错误 | 展开原始技术诊断 |

保持、恢复、停放、失能不是同义动作；不要为统一长度而省略决定行为差异的词

状态必须与数据模型对应

- **已配置**：存在所需参数；不等于已测量或验证通过
- **已测量**：对应测量确已完成；缺测范围另行标明
- **验证通过**：明确的验证条件已经满足
- **未完成**：写出尚缺哪项、原因或可以采取的下一步
- **正在加载 / 正在刷新**：请求仍在进行；请求结束后立即改为结果
- **已选择**：用户选择了值；与保存成功、实际生效分别表达

例如“刚性、拖拽、伺服跟踪已测量；柔性待补测”比含糊的“部分完成”更有用；若界面只有配置证据，就不能写成上述测量结果

不把无法获取的值填成成功、零值或空列表；使用“未读取”“暂无反馈”等与原因相符的状态，技术原因可进一步展开

## 说明放在决定发生的位置

按钮禁用时在附近说明真实条件，例如“连接工作台后可使能机械臂”；将说明关联到使能按钮，同时保留其他操作自己的可用条件

设置下方说明本项的重要影响：三维后端切换是否需要重启、当前值是否临时生效、保存是否写入 Profile；不在每个设置后重复整套系统背景

字段标签贴近输入，单位与数值关联；位置单位 `° / rad`、速度与力矩单位准确区分；表头已声明单位时，行内不必机械重复，但不能让横向查看后失去单位上下文

同一表中分开最终误差、过程峰值、RMS、参考轨迹等不同指标；“辅助”或“参考”只放在确实改变使用方式的指标附近，不覆盖所有正常结果

需要解释错误时，先写发生了什么和用户能做什么；精确错误码、路径、栈与上下文放在可复制的技术诊断中

```text
模型加载失败
无法读取指定的网格文件；检查模型路径后重新加载
▸ 原始技术诊断
```

这只是结构示例；原因必须来自实际错误，不能用同一句“检查路径后重试”包住权限、格式和图形上下文等不同失败

## 减少防御性文案

保留影响选择的限制、依赖、未完成项和风险；删除重复免责声明、空泛提示和内部流程叙述

- 不在每一行正常数据后追加“仅供参考”
- 不用“为了确保安全与准确，请谨慎操作”替代具体前置条件
- 不把实现细节、测试过程、内部模块名写进普通用户步骤
- 不隐藏真正的失败，也不通过夸大的“成功”“就绪”掩盖缺项
- 错误只在最相关位置报告一次；需要多处呈现时保持同一事实来源

重写时保持原意、数值、条件与动作范围；不根据一句抱怨自动添加新的确认步骤、警告或禁止条件

## 字段、焦点与语义

Web 使用真实 button、input、label、details、dialog 等语义，或目标框架等价控件；自绘只改变视觉，不移除基本交互能力

- label 的 `for` 与输入 id 一一对应；关节滑动条与数值输入名称能说明对象和单位
- 图标按钮有准确 `aria-label`；纯装饰图标不重复播报
- 内联错误使用稳定 id 与 `aria-describedby` 关联；无效值使用相符的 invalid 状态
- 展开控件与菜单的可访问状态跟随实际 open 状态，不只改一个 class
- 当前页、选中值、焦点和 disabled 分别表达，不混用 `aria-selected`、`aria-current` 与 `aria-pressed`
- 同一工作页避免重复 id；局部重渲染保留合理焦点，不把用户送回 body 或页面顶部

可见焦点与 hover 同等重要；不能为“干净”去掉 focus ring；若控件真的 disabled，不能依赖它接收焦点才能解释禁用原因

菜单和选择器使用与所选模式相符的键盘操作；模态对话框打开后焦点进入，关闭后返回触发上下文；非阻塞状态浮层保持原焦点

页面或模型加载不应把必要控制藏到不可达滚动区；固定工具栏与 sticky 页头不得遮挡当前焦点和错误字段

## 状态播报不跟着刷新刷屏

短操作的非阻塞浮层使用 `role="status"` 和合适的 live region；请求进行、成功或失败各播报相应转换；不要把整个实时遥测面板设成持续播报区

状态节点可使用 `aria-live="polite"`、`aria-atomic="true"`；严重故障是否需要立即播报由真实紧急程度决定；无关的周期刷新不重复播报相同结果

若设置使用原生 checkbox，保留其原生 checked 行为；添加 switch 角色时同步 checked 语义，避免视觉、DOM 属性和可访问树相互矛盾

## 偏好适配与检查边界

减少动态时停用相应 spring 或使用弱化反馈，操作和状态转换仍完整；减少透明度时改用不透明表面；高对比度时增强真实边界，不靠阴影表达分区

不要通过禁用所有反馈来实现减少动态；加载结果、选中状态、焦点和错误仍必须可辨认；具体动效行为见 [动效与滚动](motion-and-scroll.md)

按最终显示检查浅色与深色、中文与英文、窄窗口、长路径与较长关节名；检查文字溢出、控件对应、焦点遮挡和滚动末端，选择与改动相关的场景

准确区分检查结果：结构、键盘、视觉、屏幕阅读器与色彩对比度各有证据；不能因为浏览器没有报错或用了原生控件，就宣称整体可访问性合格

双主题、状态及透明叠层的对比度要求见 [主题规范](theme-guidelines.md)；报告实际结果，不擅自宣称 WCAG 等级，也不把工程验证备注加入正常产品文案

## 数据内容构图

每个面板承担一个明确任务，标题写对象和用途；图表标题写测量对象，图例明确 measured / target / estimated / reference，数值附单位、精度和必要时间上下文

空数据、断流、加载失败分别写当前情况和真实可用的下一步；不重复展示同一事实，不用装饰性文案填空白；数据语义与非颜色编码见 [可视化主题](visualization-theme.md)
