# 步骤.md 模板

> Revision: YYYY-MM-DD  
> 原则: 只推进当前主线所需能力，不把工程实现扩展成完整研究项目

# 1 本次唯一目标

用一句话说明本次只实现什么

# 2 本次明确不做

- 不做与当前目标无关的重构
- 不新增当前目标不需要的抽象层或框架
- 不做当前完成标准不需要的 benchmark
- 不做当前完成标准不需要的长稳或扩展实验
- 不在当前步骤完成前主动更新 README、CHANGELOG、设计文档、其他计划文档或与本步骤无关的项目文档
- 如果某个项目文档本身就是当前步骤明确要求的交付物，只允许做该步骤所需的最小修改

# 3 当前已完成基线

只列已经有代码、测试、日志、真实数据或其他证据支撑的完成项

不要把已完成能力再次列为实施步骤

# 4 完成标准

- [ ] 只列能够直接证明本次唯一目标完成的条件

# 5 最低成本验证路径

按本任务实际需要裁剪

1. 静态检查 / 配置检查
2. 现有单元或组件测试
3. build / lint / compile
4. simulation / replay / CSV / rosbag
5. 台架或子系统真机
6. 整机真机

能由较低层证据直接证明时，不升级到更高成本验证

# 6 总执行 Prompt

下面内容必须附加到每一个步骤的 Codex Prompt 前面

```text
你正在修改现有项目

本次只完成当前步骤定义的目标，不主动扩大范围，不顺带重构，不新增当前步骤未要求的抽象层、管理器、插件系统、通用框架或额外 capability

开始修改前先读取当前仓库中与本步骤直接相关的源码、测试、配置和必要文档，确认现有实现方式、命名方式、目录组织、错误处理方式、日志格式、代码风格和注释格式

代码阅读、架构理解和修改点定位默认属于本步骤前置动作，不单独扩展为主步骤

所有新增或修改代码必须优先沿用项目当前已经存在的代码风格、命名方式、类与函数组织方式、错误处理模式、日志风格和注释格式

禁止为了个人偏好统一格式或顺手重构邻近代码

如果项目已有类似能力或已有公共接口，优先复用，不建立重复实现

代码注释必须参考相邻代码的既有风格，注释语言、Doxygen 形式、缩进、标签和排版必须与项目现有习惯保持一致

在当前步骤完成前，不主动更新 README、CHANGELOG、设计文档、其他计划文档或与本步骤无关的项目文档

仅允许修改当前步骤明确要求的源码、配置、测试、必要资源文件，以及更新本文档的进度状态和必要备注

如果某个项目文档本身就是当前步骤明确要求的交付物，只允许做该步骤所需的最小修改

自然语言说明、Markdown 新增内容和 Codex 汇报中禁止使用中文句号

自然语言段落末尾不要添加句号、逗号、分号、冒号、感叹号、问号等标点

上述自然语言标点规则不适用于 C++ / Python / YAML / CMake / shell 等代码语法，也不得为了满足该规则破坏项目既有代码或注释语法

不要新建分支，不要切换分支，不要执行 git commit，不要执行 git push

验证时优先使用能够直接证明完成标准的最低成本证据
如果静态检查、已有测试、构建、仿真、回放或记录数据已经足够证明当前标准，不要为了保险增加更高成本的台架或真机实验

完成后只汇报
1 修改了哪些文件
2 每个文件修改了什么
3 实际执行了哪些验证命令
4 每条验证的真实结果
5 是否存在尚未验证或仍需真机确认的内容

没有执行过的测试不能写成 PASS

没有真实 CSV / rosbag / 真机数据支撑的真机 Gate 不能写成 PASS

如果当前步骤属于重要代码修改并且 requesting-code-review 可用，在最终完成前调用它进行审查

在任何步骤被标记为完成前，如果 verification-before-completion 可用，调用它检查新鲜验证证据

如果执行中发现新问题，先判断它是否阻塞当前唯一目标

如果不阻塞，将其记录到 Later Optional，不修改当前进度统计

如果阻塞，只允许基于新证据对受影响部分做最小增量修改，保留已经完成和仍然有效的步骤，不得因为新增可选工作直接重写整套大型计划

允许从 S 升级到 M 或从 M 升级到 L，但只能增量补充必要步骤
```

# 7 实施步骤

## 步骤 1 `[ ]` 任务名称

### 前置条件

仅在确实存在前置条件时保留

### 目标

一句话说明这一步完成什么

### 修改范围

- 只列直接相关文件或模块

### 必做

- 必须实现的最小内容

### 禁止

- 本步骤最容易发生的 scope creep

### 最小验证

- [ ] 能直接证明本步骤目标的最低成本检查项

### Codex Prompt

```text
先读取本步骤直接相关的现有代码、测试、配置和必要文档

本步骤只完成这里定义的目标

说明允许修改的范围和明确禁止的扩展

优先复用现有实现和接口

只执行完成标准真正需要的最低成本验证

完成后报告真实修改与真实验证结果
```

重复步骤结构直到主线完成

## Investigation Step 例外

只有存在阻塞实现的具体技术不确定性，并且普通实施步骤内的代码检查无法消除时才允许单独建立 Investigation Step

必须写明

- 要回答的具体问题
- 为什么它阻塞实现
- 最小调查范围
- 明确退出条件
- 调查结果如何决定下一步

禁止用模糊的 分析项目 理解代码 设计方案 检查架构 作为独立主步骤
