# 精简步骤.md 模板

> Revision: YYYY-MM-DD  
> 原则: 用最少真实步骤完成并验证当前唯一目标

# 1 目标与边界

**本次唯一目标**

用一句话说明本次只实现什么

**不做**

- 只列最容易发生且会扩大范围的内容

**已完成基线**

- 只列已有代码、测试、日志、数据或其他证据支撑的完成项

**完成标准**

- [ ] 能直接证明当前目标已经完成的条件

# 2 总执行 Prompt

下面内容必须附加到每一个步骤的 Codex Prompt 前面

```text
你正在修改现有项目

本次只完成当前步骤定义的目标，不主动扩大范围，不顺带重构，不新增当前步骤未要求的抽象层、管理器、插件系统、通用框架或额外 capability

开始修改前先读取当前步骤直接相关的现有源码、测试、配置和必要文档，确认当前实现方式和项目风格

优先复用现有接口和模式，只修改完成当前步骤所必需的文件

代码阅读、架构理解和修改点定位属于当前步骤的前置动作，不单独扩展成新的主步骤

在当前步骤完成前，不主动更新 README、CHANGELOG、设计文档、其他计划文档或与本步骤无关的项目文档

不要新建分支，不要切换分支，不要执行 git commit，不要执行 git push

验证时优先使用能够直接证明完成标准的最低成本证据，不为保险重复增加更高成本实验

自然语言说明、Markdown 新增内容和 Codex 汇报中禁止使用中文句号

自然语言段落末尾不要添加句号、逗号、分号、冒号、感叹号、问号等标点

上述自然语言标点规则不适用于 C++ / Python / YAML / CMake / shell 等代码语法，也不得为了满足该规则破坏项目既有代码或注释语法

完成后只汇报
1 修改了哪些文件
2 每个文件修改了什么
3 实际执行了哪些验证命令
4 每条验证的真实结果
5 是否存在尚未验证或仍需真机确认的内容

没有执行过的测试不能写成 PASS
没有真实证据支撑的真机 Gate 不能写成 PASS

如果执行中发现新问题，先判断它是否阻塞当前目标
不阻塞则记录到 Later Optional
阻塞则只对当前计划做最小增量修改，不重写整套计划

如果当前步骤属于重要代码修改并且 requesting-code-review 可用，在最终完成前调用它进行审查

在任何步骤被标记为完成前，如果 verification-before-completion 可用，调用它检查新鲜验证证据
```

# 3 实施步骤

## 步骤 1 `[ ]` 任务名称

**目标**

一句话说明这一步完成什么

**修改范围**

- 只列直接相关文件或模块

**必做 / 禁止**

- 必须实现的最小内容
- 最容易发生的 scope creep

**最小验证**

- [ ] 使用最低成本且足以证明本步骤目标的检查

**Codex Prompt**

```text
先读取本步骤直接相关的现有代码、测试、配置和必要文档
本步骤只完成这里定义的目标
优先复用现有实现和接口
只修改明确允许的范围
只执行完成标准真正需要的最小验证
完成后报告真实修改与真实验证结果
```

按需重复步骤结构

# 4 最终验收与立即执行

- [ ] 当前唯一目标已经实现
- [ ] 每个 PASS 都有对应的新鲜证据
- [ ] 没有扩大到明确不做的内容

**当前立即执行**

只写一个下一步

**Later Optional**

只记录不影响当前完成条件的后续工作
